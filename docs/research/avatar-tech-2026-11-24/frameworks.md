# Real-time avatar frameworks: Mynah vs Vivora vs OpenAvatarChat

Research date: 2026-11-24. Method: I shallow-cloned each repository (plus SoulX-FlashHead, MuseTalk, lite-avatar and LAM) and read the README, LICENSE, requirements files, setup and download scripts and handler code. I queried the Hugging Face model and Space APIs and the ModelScope API, and fetched GitHub pages for stars and issue counts. Nothing was run. No numbers below are my own measurements: every performance figure is what the project itself says.

Context: DateWise has 4 coaches (2 English, 2 Mexican Spanish), one portrait each, an iPhone Flutter client, a Cloudflare Worker backend, a $0 budget, and must use only commercially licensed code, models and dependencies.

## 2. Detail with sources

### 2.1 Mynah (honwee/mynah)

- **What it is.** A deployable "digital human" stack. The Go `cored` takes a WebRTC offer, opens a gRPC stream to a Python avatar worker, feeds it TTS audio, and paces VP8/H.264 + Opus back to the browser. ASR, semantic turn-taking, LLM brains (local, Qwen realtime, Pipecat), RAG, an admin console and published channels are all included. Source: README "What it is" and "Architecture" ([README](https://github.com/honwee/mynah/blob/main/README.md)).
- **Engines.** Default is FlashHead Lite. The worker loads `model_type="lite"` (`workers/avatar/flashhead_engine.py`). MuseTalk 1.5 and wav2lipLS are optional. The engine is pluggable through `proto/avatarengine/v1` ([LICENSING.md](https://github.com/honwee/mynah/blob/main/LICENSING.md), [docs/guide/avatars.md](https://github.com/honwee/mynah/blob/main/docs/guide/avatars.md)).
- **Single photo.** "FlashHead needs only a single portrait (no bake) but is a 512² head-and-shoulders model." A half-body variant pastes the 512 face back onto a 720×1280 canvas ([docs/guide/hardware.md](https://github.com/honwee/mynah/blob/main/docs/guide/hardware.md), [avatars.md](https://github.com/honwee/mynah/blob/main/docs/guide/avatars.md)). Training from video (10–20 s) is a separate path for MuseTalk and wav2lipLS.
- **Idle behaviour.** "Idle costs no GPU: silence is a baked loop replayed by cored." Idle and gesture clips are baked with LivePortrait. The "instinct layer" picks a gesture while the LLM is still composing ([README "Performance"](https://github.com/honwee/mynah/blob/main/README.md), `docs/guide/instinct.md`). Blinking and breathing come from the baked loop ("so the avatar breathes and blinks instead of freezing").
- **Latency, barge-in.** See the README Performance table (RTX 4090, 2026-10-11). Barge-in uses `POST /interrupt_talk`. The turn detector is Smart Turn v3.2 (BSD-2), bundled as ONNX.
- **Hardware and concurrency.** "One avatar worker serves one live session at a time". FlashHead runs at "1.56× realtime on a 4090, i.e. one GPU ≈ one concurrent visitor". A 24 GB card runs 2–3 sessions as a pool ([README "Capacity & scaling"](https://github.com/honwee/mynah/blob/main/README.md)). Multi-worker routing is "on the roadmap, not in the box".
- **Spanish.** Lip-sync is driven by audio features: wav2vec2-base-960h for FlashHead ([setup-flashhead.sh](https://github.com/honwee/mynah/blob/main/deploy/compose/setup-flashhead.sh)), which was trained on English LibriSpeech. Expect it to work on Spanish phonemes, but it needs testing. The ASR worker is SenseVoice (`workers/asr/server.py`), whose languages do not include Spanish. DateWise already recognises speech on the device, so it can POST text to `/human` with `type:"echo"` or `"chat"`. TTS is any OpenAI-compatible `/v1/audio/speech`, so DateWise's existing voices could be wrapped. The default EdgeTTS calls Microsoft's unofficial Edge read-aloud endpoint, which is a ToS risk for commercial use.
- **Licences.**
  - Code: Apache-2.0 ([LICENSE](https://github.com/honwee/mynah/blob/main/LICENSE)).
  - FlashHead code: Apache-2.0 ([SoulX-FlashHead LICENSE](https://github.com/Soul-AILab/SoulX-FlashHead/blob/main/LICENSE)). **The weights are tagged `license: other` on Hugging Face and the repo has no licence file** ([model card](https://huggingface.co/Soul-AILab/SoulX-FlashHead-1_3B)). In discussion #1, "Can this model be used for commercial purposes?", the team member replied "Of course you can, but you must abide by the laws of China and the laws of your country. We assume no legal responsibility." Discussion #2, an open request from a company for a formal commercial licence, notes the same gap ([discussions](https://huggingface.co/Soul-AILab/SoulX-FlashHead-1_3B/discussions)). **This is the main licence risk.** Get a written grant (an email or a LICENSE file in the repo) before production.
  - FlashHead **Lite** decodes with `VAE_LTX` (a Lightricks LTX-Video causal VAE; repo file list). Mynah's LICENSING.md itself flags "verify Lightricks' LTX terms". LTX ≥ 0.9.6 uses the LTXV Open Weights License, which is free only for entities under **$10M annual revenue** ([licence text](https://huggingface.co/Lightricks/LTX-Video/blob/main/LTX-Video-Open-Weights-License-0.X.txt)). Earlier versions used OpenRAIL-M. The exact LTX version embedded is not stated. The Pro model uses the Wan 2.1 VAE (Apache-2.0) but runs at only 10.8 fps on a 4090.
  - wav2vec2-base-960h: Apache-2.0 ([HF](https://huggingface.co/facebook/wav2vec2-base-960h)).
  - wav2lipLS 256: "self-trained" weights published as a release asset, training data not disclosed ([LICENSING.md](https://github.com/honwee/mynah/blob/main/LICENSING.md)). Treat as unclear.
  - LivePortrait (idle baking): MIT, but `requirements-avatartrain.txt` pins `insightface==1.0.1`. The bake script runs with `--no-flag_do_crop` to bypass it. InsightFace models are non-commercial, so make sure the `buffalo_l` models are never downloaded or used, or remove the package.
  - SenseVoice and Qwen3-TTS: "per upstream" (not audited here; not needed if DateWise uses its own ASR and TTS).
- **iPhone Flutter.** The signaling is plain: `POST /offer {sdp,type}` returns `{sdp,type:"answer",sessionid}`. `flutter_webrtc` can do this directly. The response comes wrapped as `{code:0,data:…}`. `cored` takes `--stun` and `--ice-tcp` flags but I found **no TURN-relay flag**, so cellular users behind symmetric NAT will need a TURN server (for example coturn, BSD, self-hosted) and a small code change to advertise it.
- **Maturity.** 324 stars, 110 forks, 2 open issues, 3 commits: initial release 2026-10-12, last commit 2026-10-24 ([repo](https://github.com/honwee/mynah)). It is very young, and the git history is a squashed single drop.
- **Demos.** `assets/demo/mynah-demo.gif` and `mynah-luna-demo.gif` in the repo. An AutoDL community image exists (China-centric). I found no free Hugging Face Space.
- **Testable here?** The avatar engines cannot run without a CUDA GPU. Only `cored` and the console would run, pointed at a remote worker.

### 2.2 Vivora (sur950/vivora)

- **What it is.** A polished full-stack demo app (auth, history, Terraform). It is **not a real-time video stream**. Each LLM sentence → Chatterbox TTS → MuseTalk renders an MP4 → the URL goes over a WebSocket (`video_chunk` events) ([README "How a turn flows" / "The API"](https://github.com/sur950/vivora/blob/main/README.md)).
- **Single photo.** "Upload a clear frontal photo and Vivora lip-syncs the mouth on a still frame." Head movement requires a video avatar ([README](https://github.com/sur950/vivora/blob/main/README.md); `backend/app/services/animator.py`). There is no idle, blink or breathing behaviour for photos.
- **Spanish.** faster-whisper (multilingual), Chatterbox Multilingual (23 languages including es), and `set_language` over the WebSocket. This is the best Spanish story of the three, but its parts are commodity components.
- **Performance.** CPU: "30–90 s per sentence". GPU: it cites MuseTalk's about 30 fps at 256² on a V100 (from the paper, not measured by Vivora). It suggests g5.xlarge spot at about $0.30/h ([README](https://github.com/sur950/vivora/blob/main/README.md)).
- **Licences.** Code: MIT ([LICENSE](https://github.com/sur950/vivora/blob/main/LICENSE)). MuseTalk weights: MIT, but the NOTICE says "trained on the HDTF and private dataset. Please, communicate with the HDTF owner about commercialization issues" ([NOTICE](https://huggingface.co/TMElyralab/MuseTalk/blob/main/NOTICE)). `scripts/setup_musetalk.sh` downloads the BiSeNet face-parser `79999_iter.pth` from Google Drive (zllrunning, code MIT, trained on CelebAMask-HQ, a non-commercial dataset), plus sd-vae-ft-mse (MIT) and whisper-tiny (MIT). It swaps mmpose for `face-alignment` (BSD-3 code; the provenance of the S3FD/FAN weights is not stated). The gTTS fallback uses Google Translate's unofficial endpoint, and edge-tts uses Microsoft's unofficial endpoint.
- **iPhone Flutter.** Easy: `web_socket_channel` plus `video_player`. Playback is clip by clip, though, so gaps between sentences and no listening state.
- **Maturity.** 10 stars, 3 forks, **1 commit** (2026-07-07) ([repo](https://github.com/sur950/vivora)).
- **Testable here?** Yes for the "simple" engine. MuseTalk on CPU could render a short offline clip of a coach photo in about an hour, if downloading the ~9 GB of weights is allowed. That only shows MuseTalk's quality, not real-time behaviour.

### 2.3 OpenAvatarChat (HumanAIGC-Engineering/OpenAvatarChat)

- **What it is.** A configurable pipeline framework. Each preset YAML wires the Client, VAD (Silero / Smart Turn), ASR (SenseVoice / Bailian), LLM (OpenAI-compatible / Qwen-Omni / Dify / Agent beta), TTS (CosyVoice local, Bailian, Edge) and an Avatar handler ([readme_en.md](https://github.com/HumanAIGC-Engineering/OpenAvatarChat/blob/main/readme_en.md), [how-it-works](https://humanaigc-engineering.github.io/OpenAvatarChat/en/guide/how-it-works)). v0.6.0 (2026-04) split out a separate WebUI and added FlashHead and universal interrupt support.
- **Avatar engines it plugs in**
  - **LiteAvatar** ([HumanAIGC/lite-avatar](https://github.com/HumanAIGC/lite-avatar), MIT code): "can run in 30fps on only CPU devices". Every avatar is a pre-built package (a `bg_video.mp4`, per-avatar `net.pth/net_encode.pt/net_decode.pt` and ref frames, found by inspecting `data/sample_data.zip`) from a 100-avatar gallery ([LiteAvatarGallery](https://modelscope.cn/models/HumanAIGC-Engineering/LiteAvatarGallery), no licence on its ModelScope record). **The tool to build an avatar from our own photo or video is not released**, so it cannot show our coaches. Audio features come from the **Chinese** Paraformer (Apache-2.0 on ModelScope). The last lite-avatar commit was 2025-06-30.
  - **LAM** ([aigc3d/LAM](https://github.com/aigc3d/LAM)): one image → animatable 3D Gaussian head in about 1.4 s, rendered **on the client** in WebGL ("110+ FPS on a Xiaomi 14"). Code is Apache-2.0, but **`LICENSE_WEIGHT` is CC BY-NC 4.0** (added 2026-06-10) ([LICENSE_WEIGHT](https://github.com/aigc3d/LAM/blob/main/LICENSE_WEIGHT)). It also depends on FLAME (`chumpy`; the MPI licence is non-commercial), `diff-gaussian-rasterization` (Inria, non-commercial) and `nvdiffrast` (NVIDIA Source Code License, non-commercial) ([requirements.txt](https://github.com/aigc3d/LAM/blob/main/requirements.txt)). LAM_Audio2Expression weights are Apache-2.0 ([HF](https://huggingface.co/3DAIGC/LAM_audio2exp)), but the avatar itself is non-commercial. **Cannot be used.**
  - **MuseTalk 1.5**: as described for Vivora. OAC replaced mmpose with a DWPose ONNX model (`musetalk_utils_preprocessing.py`) and takes a video or a folder of images (`avatar_video_path`). `concurrent_limit: 1` in the preset.
  - **SoulX-FlashHead Lite**: single image (`cond_image_path`). OAC keeps the model running on low-amplitude "breathing-patterned noise" audio while idle (`flashhead_processor.py`, `idle_noise_amplitude`), so the GPU stays busy even when the avatar is silent. The duplex preset sets `concurrent_limit: 1 # FlashHead GPU 显存占用较高，建议单路` ("FlashHead uses a lot of GPU memory; one session recommended") ([config](https://github.com/HumanAIGC-Engineering/OpenAvatarChat/blob/main/config/chat_with_openai_compatible_bailian_cosyvoice_flashhead_duplex.yaml)). Same weight-licence issues as under Mynah.
- **Latency.** "average response delay is about 2.2 seconds" (i9-13900KF + RTX 4090) ([docs](https://humanaigc-engineering.github.io/OpenAvatarChat/en/guide/how-it-works)).
- **Deployment.** CUDA ≥ 12.8, git-lfs, flash-attn compilation for FlashHead. For public access, "Both SSL certificate and TURN service are NON-NEGOTIABLE", and a coturn script and Docker setup are included ([deployment](https://humanaigc-engineering.github.io/OpenAvatarChat/en/guide/deployment)). TURN support is better than Mynah's.
- **Spanish.** The default ASR is SenseVoice (no Spanish). Bailian ASR and CosyVoice are Alibaba cloud services (paid accounts). Edge TTS is an unofficial endpoint. DateWise would add its own ASR and TTS handlers.
- **iPhone Flutter.** The RTC client is `fastrtc` (MIT, a fork of gradio-webrtc). Signaling is an HTTP offer/answer, but a native client must copy the WebUI's protocol (webrtc_id, data channel messages). That is doable with `flutter_webrtc`, but it is more reverse-engineering than with Mynah.
- **Maturity.** 3.9k stars, 638 forks, 150 open issues, 15 open PRs, 95 commits, last commit 2026-07-31 ([repo](https://github.com/HumanAIGC-Engineering/OpenAvatarChat)). This is the most established of the three.
- **Demos.** README videos (LiteAvatar, LAM). The [HF "Space"](https://huggingface.co/spaces/HumanAIGC-Engineering-Team/open-avatar-chat) is `sdk: static` and iframes `open-avatar.holoworld.com.cn` (built-in avatars only). The [FlashHead Space](https://huggingface.co/spaces/Soul-AILab/SoulX-FlashHead) runs on `zero-a10g` (needs a ZeroGPU quota). The [LAM Space](https://huggingface.co/spaces/3DAIGC/LAM) runs on `cpu-basic` (but the weights are non-commercial). The [MuseTalk Space](https://huggingface.co/spaces/TMElyralab/MuseTalk) shows `RUNTIME_ERROR`.
- **Testable here?** Only LiteAvatar on CPU, with a gallery face. FlashHead and MuseTalk need CUDA.

## 4. Licence red flags, summarised

1. **SoulX-FlashHead weights**: `license: other`, no licence file. Only an informal "of course you can" reply on Hugging Face. **Get it in writing.**
2. **LTX-Video VAE** inside FlashHead Lite: LTXV Open Weights License if version ≥ 0.9.6 (free under $10M revenue, paid above). Version not stated.
3. **MuseTalk**: weights MIT, but trained on HDTF with an explicit note to clear commercialization with HDTF. BiSeNet face-parse weights trained on CelebAMask-HQ (non-commercial).
4. **LAM**: CC BY-NC 4.0 weights, FLAME, Inria rasterizer, nvdiffrast. **Excluded.**
5. **InsightFace**: present in Mynah's avatartrain requirements (bypassed by a flag). Remove it or make sure it is never invoked.
6. **wav2lipLS** (Mynah): training data not disclosed.
7. **EdgeTTS / gTTS** defaults: unofficial consumer endpoints. Use DateWise's own TTS instead.

## 5. Ranked recommendation (for these three)

1. **Mynah.** It is the closest match: one portrait per coach (FlashHead), idle, blink, breathing and gestures with no GPU cost while listening, WebRTC with plain `/offer` signaling that `flutter_webrtc` can use, barge-in, a `/human` text entry point (so DateWise keeps its own ASR and LLM), and an OpenAI-compatible TTS hook. Caveats: a very young repository (3 commits), one session per GPU, no TURN, and the FlashHead/LTX weight licences must be cleared in writing first.
2. **OpenAvatarChat.** The mature framework with the same FlashHead engine, better TURN and deployment docs, and a large community. But idle frames keep the GPU busy, Flutter signaling is harder, and of its other engines LAM is non-commercial and LiteAvatar cannot use our faces.
3. **Vivora.** It is not real-time (clip per sentence), animates only the mouth on photos, has 1 commit, and carries MuseTalk's HDTF caveat. Its parts (faster-whisper, Chatterbox) are worth reusing, not the app.

None of the three can be truly tested on this CPU-only machine. A real evaluation needs an owner-approved GPU rental (FlashHead Lite on one 4090 or A10G-class card, about 1–2 h) or a written licence answer first.
